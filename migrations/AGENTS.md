# Schema changes

While this file exists, MuseFlow is in development: no server runs in production, so the schema changes without
migrations. When that ends, this file is deleted and schema changes become ordinary Alembic revisions.

- **Never add a revision.** `versions/initial.py` is the only one, regenerated by Alembic at each schema change. Never
  edit it by hand, and never write a data patch or a `backfill_*` method: a reset empties the database, the imports
  or a new computation fill it again.
- **A schema change resets the database**, without losing what was paid for (LLM results) or typed by the user
  (ratings, blacklist):
  1. `make backup-export`, *before* changing the models: the exports read the current schema. It also writes a full
     SQL dump, the way back with the current code (`make db-restore`).
  2. Change the models, delete `versions/initial.py`, `make reset && make up`, `make db-revision`, then rename the
     generated file to `initial.py`.
  3. `museflow users create`, `make backup-import` (migrations, history, then the exports), `museflow provider connect`.
- **The reset is the user's call.** `make backup-export` is free and read-only; `make reset` destroys the local
  database: ask before running it.
- Data a reset still loses (anything without an export/import, e.g. the LLM usage until #150) is named in the PR.
